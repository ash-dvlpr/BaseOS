# Start from charging while POWER is held

The charger fallback previously accepted a half-second hold only when the
button was released. A user waiting for the power LED or BaseOS logo had no
cue to release it, and could keep holding until the PMIC's hardware shutdown
threshold. This was a userspace input-policy problem; the PMIC poweroff
register and its power-key timing are unchanged by this correction.

## Change

`charger-wait` keeps an infinite `poll()` timeout while idle. A fresh POWER
press sets a one-second deadline; reaching it starts the same boot without waiting
for release. A short release or lost input cancels the deadline, and repeats
and signals cannot extend it. The evdev file uses `CLOCK_MONOTONIC`, so queued
press/release events retain their actual duration.

After the hold is accepted, `baseos-charger` restores brightness and the CPU
governor, lights the power LED, and draws the existing BaseOS logo once before
normal initialization. No renderer runs during idle charging. Normal boots
skip this helper entirely. One second matches the RG34XX SP's observed PMIC
ONLEVEL setting (`REG26H=0x16`); the visible cold-boot delay also includes
bootloader/display initialization. The draw uses `fbsplash 100`, matching the fully
illuminated wordmark generated by `tools/make-bootlogo.sh`.

## Automated checks

`tests/test-poweroff-policy.sh` passes. The input tests include a press that is
never released: the producer waits for the helper's success while keeping the
input descriptor open. They also cover a key held on entry, short taps,
`SYN_DROPPED`, delayed short/long event batches, and repeated input/signals.
The existing PMIC transaction and filesystem checks pass unchanged.

The shell tests verify that the LED and logo stay inactive before accepted
input, that the governor and brightness are restored before rendering, that
the logo is drawn once before GPU initialization, and that a failed draw does
not block startup. Normal, MENU, and opt-out boots do not draw this logo.

The ARM64 helper compiles with `-O2 -Wall -Wextra -Werror`. A read-only probe
confirmed `EVIOCSCLOCKID(CLOCK_MONOTONIC)` on the RG34XX SP vendor kernel.

## Device check

The corrected helper and shell script were installed on the RG34XX SP over
build `c4a7aaa`. A saved timestamp temporarily selected the existing loop-guard
fallback for the physical hold-until-feedback check. No USB diagnostic gadget
was started in the charging wait.

The user confirmed the LED/logo appeared while POWER was still held. Slot
started in that same charger boot (`28ae5acd-56c3-4625-8ece-015cc1bd6b5b`,
latched `boot_mode=1`), and the CPU governor returned to `performance`. The
timestamp was restored afterward. The first test used a 500 ms threshold and splash progress 0,
revealing the old partially lit wordmark; the final call uses 100 to match
the bootloader logo, and the final threshold is one second. The regression
tests exercise the final threshold without releasing POWER.
